# Эхо — контракт API для фронтенда (v10.30)

> **Действующий контракт интеграции (27.10.2026):** [API_LIVE.md](API_LIVE.md). Эта страница описывает исходный контракт макета EchoWeb. В текущей сборке `src/app.js` использует `src/echo-api.js`; маршруты и формат ошибок Backend отличаются от описанных ниже.

Документ описывает, какие запросы делает интерфейс и какие данные он ожидает в ответ.
Весь обмен с сервером находится в одном файле: `src/api.js`. Интерфейс в других местах к серверу не обращается.

## Общие правила

- **Базовый адрес** задаётся переменной `VITE_API_URL` в файле `.env`. Пустое значение включает демо-данные из `src/mock-data.js`.
  Рекомендуется отдавать API с того же домена через nginx по пути `/api` и указать `VITE_API_URL=/api`: тогда CORS не нужен.
- **Формат:** JSON, кодировка UTF-8. Тело запроса передаётся с заголовком `Content-Type: application/json`.
- **Сессия:** cookie (`credentials: 'include'`). Если нужен токен, его добавляют в функцию `request()` в `src/api.js` в одном месте.
- **Ошибки:** HTTP-статус 4xx/5xx и тело `{ "message": "Текст для пользователя" }`. Текст показывается во всплывающем уведомлении.
- **Ответ без тела:** `204 No Content` подходит для всех лайков и сохранений.
- **Даты** (`date`, `joined`) — готовые строки для показа: `"22 сентября 2026"`.
- **Оценка** — пять параметров от 1 до 10 в порядке: драматургия и структура, персонажи и исполнение, визуальный язык, звук и музыка, впечатление.
  Итог считается так: `round(среднее четырёх параметров формы × 10 × (0.4 + 0.6 × (впечатление − 1) / 9))`.
  Тот же расчёт есть во фронте (`calcReviewTotal`), но источником истины должен быть сервер.
- **id фильмов** могут быть любыми числами. Фронт сам переводит их во внутренние индексы.

## 1. Загрузка при старте

При открытии сайта фронт делает параллельно шесть запросов:

| Запрос | Что вернуть |
|---|---|
| `GET /movies` | массив фильмов |
| `GET /reviews` | массив опубликованных рецензий (все фильмы) |
| `GET /authors` | массив авторов |
| `GET /people` | кандидаты для топ-5 режиссёров и актёров |
| `GET /users` | публичные профили зрителей и медиа |
| `GET /auth/me` | текущая сессия или `401`, если вход не выполнен |

Для MVP подходят полные списки. Когда данных станет много, можно перейти на постраничную загрузку; тогда меняется только `src/api.js`.

### Фильм — `GET /movies`
```json
{
  "id": 1,
  "title": "Дюна: Часть вторая",
  "year": 2024,
  "genre": "Фантастика",
  "director": "Дени Вильнёв",
  "country": "США, Канада",
  "poster": "https://…/dune2.jpg",
  "desc": "Пол Атрейдес объединяется с Чани…",
  "reviews": 1284,
  "ratings": 18420,
  "preferred": 12482,
  "scoreSets": {
    "reviews": { "total": 86, "parts": [8, 7, 10, 9, 9] },
    "ratings": { "total": 83, "parts": [8, 8, 10, 8, 9] },
    "critics": { "total": null, "parts": [] }
  },
  "authorComment": {
    "title": "О ритме и масштабе",
    "author": "Дени Вильнёв",
    "role": "Режиссёр",
    "avatar": "https://…/villeneuve.jpg",
    "text": "Мне было важно…",
    "likes": 1482,
    "likedByMe": false,
    "date": "18 сентября 2026"
  },
  "crew": {
    "actors": [{ "name": "Тимоти Шаламе", "role": "Пол Атрейдес", "image": "https://…" }],
    "team":   [{ "name": "Грег Фрейзер", "role": "Оператор", "image": "https://…" }]
  }
}
```
- `scoreSets.reviews` — средние по оценкам с рецензией, `ratings` — без рецензии, `critics` — по рецензиям медиа. Если оценок нет: `total: null, parts: []`.
- `preferred` — сколько пользователей добавили фильм в топ-5.
- `authorComment` — `null`, если комментария нет.

### Рецензия — `GET /reviews`
```json
{
  "id": 1,
  "movieId": 1,
  "user": "frames.by.ira",
  "avatar": "https://…",
  "status": "Лазурь",
  "kind": "user",
  "total": 86,
  "parts": [8, 7, 10, 9, 9],
  "title": "Большое кино, которое не боится тишины",
  "text": "…",
  "spoiler": false,
  "likes": 327,
  "likedByMe": false,
  "authorLikes": ["Дени Вильнёв"],
  "date": "22 сентября 2026"
}
```
- `kind`: `user` (зритель), `media`, `author` (рецензия, которую написал автор).
- `status` — статус автора рецензии на момент выдачи: светлячок для зрителя (`Искра`, `Мята`, `Лазурь`, `Аметист`, `Рубин`, `Полярный`), `Медиа` или специальность автора.
- `authorLikes` — имена авторов, поставивших лайк автора. По нему показывается плашка «★ Лайк автора» рядом с обычными лайками.
- `id` — число. Новые рецензии должны получать больший `id`: сортировка «Новые» идёт по нему.
- Сюда попадают только рецензии, прошедшие модерацию.

### Автор — `GET /authors`
```json
{
  "name": "Дени Вильнёв",
  "image": "https://…",
  "specialty": "Режиссёр · сценарист · продюсер",
  "verified": true,
  "bio": "",
  "authorRatings": 31,
  "comments": 14,
  "authorLikes": 612,
  "preferred": 48210,
  "scores": { "reviews": 89, "ratings": 87, "critics": 92 },
  "works": [
    { "id": "aw0", "title": "Дюна: Часть вторая", "year": 2024, "genre": "Фантастика",
      "director": "Дени Вильнёв", "role": "Режиссёр", "poster": "https://…",
      "reviews": 1284, "ratings": 18420, "popularity": 12482,
      "scores": { "reviews": 86, "ratings": 83, "critics": 91 } }
  ]
}
```
- Сейчас автор определяется по `name`; имена должны быть уникальными. Позже можно перейти на `id`.
- Работа из `works` ведёт на страницу фильма, только если её `title` совпадает с фильмом из `/movies`.
- От первого слова `specialty` зависит, в какой топ-5 попадает автор: «Режиссёр» — режиссёры, «Актёр»/«Актриса» — актёры. Для остальных специальностей счётчик «в предпочтениях» не нажимается.

### Кандидаты для предпочтений — `GET /people`
```json
{
  "directors": [{ "name": "Дени Вильнёв", "image": "https://…" }],
  "actors":    [{ "name": "Тимоти Шаламе", "image": "https://…" }]
}
```

### Профиль зрителя или медиа — `GET /users` и поле `user` в ответах входа
```json
{
  "nickname": "NADYA",
  "kind": "user",
  "bio": "Люблю медленное кино…",
  "avatar": "https://…",
  "joined": "12 апреля 2025",
  "points": 2840,
  "prefMovies": [1, 2, 3, 4, 5],
  "prefDirectors": ["Дени Вильнёв", "Кристофер Нолан"],
  "prefActors": ["Тимоти Шаламе", "Зендея"]
}
```
- `kind`: `user` или `media`. `points` — баллы, от них считается статус-светлячок.
- `prefMovies` — id фильмов, `prefDirectors` и `prefActors` — имена. В каждом списке не больше пяти пунктов.

### Сессия — `GET /auth/me`
- Зритель вошёл: `{ "role": "user", "user": { …профиль… } }`
- Автор вошёл: `{ "role": "author", "author": { "name": "Дени Вильнёв" } }`
- Вход не выполнен: `401`.

## 2. Вход, регистрация, выход

| Действие | Запрос | Тело | Ответ |
|---|---|---|---|
| Вход зрителя | `POST /auth/login` | `{ "login", "password" }` | `{ "user": {…} }` и cookie сессии |
| Регистрация зрителя | `POST /auth/register` | `{ "login", "password" }` | `{ "user": {…} }` и cookie |
| Вход автора | `POST /auth/author/login` | `{ "login", "password" }` | `{ "author": { "name" } }` и cookie |
| Заявка автора | `POST /auth/author/register` | `{ "login", "password", "name", "specialty" }` | `{ "pending": true }`: кабинет откроется после подтверждения |
| Выход | `POST /auth/logout` | — | `204` |

Неверный логин или пароль: `401 { "message": "Неверный логин или пароль" }`.

## 3. Действия пользователя

| Действие | Запрос | Тело | Ответ |
|---|---|---|---|
| Лайк рецензии / снять | `PUT` / `DELETE /reviews/{id}/like` | — | `204` |
| Лайк комментария автора / снять | `PUT` / `DELETE /movies/{id}/author-comment/like` | — | `204` |
| Оценка без рецензии | `POST /movies/{id}/ratings` | `{ "parts": [5 чисел] }` | `204` |
| Рецензия | `POST /movies/{id}/reviews` | `{ "title", "text", "parts", "spoiler" }` | созданная рецензия (формат `/reviews`) |
| Предпочтения | `PUT /me/preferences` | `{ "movies": [id], "directors": [имена], "actors": [имена] }` | `204` |
| Редактирование профиля | `PATCH /me` | `{ "nickname", "bio", "avatar" }` | `204` |

- Рецензия: текст от 150 до 10 000 символов (фронт проверяет, сервер должен проверять тоже), одна рецензия на фильм, без редактирования и удаления.
- После модерации рецензия попадает в `/reviews`. Если она отправляется на модерацию, ответ может вернуть её со статусом, а фронт покажет её автору сразу.
- `avatar` при редактировании профиля приходит как data URL картинки. Позже можно сделать отдельную загрузку файла.
- Лайк, лайк автора и предпочтения фронт применяет сразу, не дожидаясь ответа. При ошибке показывается уведомление.

## 4. Действия автора (Эхо Studio)

| Действие | Запрос | Тело | Ответ |
|---|---|---|---|
| Лайк автора / снять | `PUT` / `DELETE /reviews/{id}/author-like` | — | `204` |
| Опубликовать комментарий к фильму | `PUT /movies/{id}/author-comment` | `{ "title", "text" }` | объект `authorComment` (как в `/movies`) |

- Автор может ставить лайк автора и писать комментарий только к своим фильмам. Это должен проверять сервер.
- Обычные лайки автору недоступны, фронт их не отправляет.
- Новый комментарий заменяет предыдущий комментарий этого автора к фильму, лайки обнуляются.
