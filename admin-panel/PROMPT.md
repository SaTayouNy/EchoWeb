# Промпт: административная панель «Эхо»

> Постановка задачи, по которой собрана панель. Написана на основе бэкенда из `hosting/v10.40`, схемы БД (миграции V1–V16), фронтенда v10.40 и документов проекта (требования, бизнес-логика, правила рецензий, аналитика).

## Роль и цель

Ты — продуктовый дизайнер и фронтенд-разработчик внутренних инструментов. Сделай веб-страницу административной панели «Эхо» — платформы оценок и рецензий на кино. Панелью пользуются 1–3 человека из команды (PM и модераторы) каждый день: им важно быстро разбирать очередь, ничего не пропускать и видеть, кто и что сделал.

## Что известно о системе

- **Бэкенд:** Spring Boot.
  - Авторизация по JWT: `POST /v1/auth/login {username,password}` → `{accessToken, refreshToken}`; обновление — `POST /v1/auth/refresh {refreshToken}`.
  - Текущий пользователь: `GET /v1/me` → `{userId, username, role, isActive, createdAt, …}`.
- **Роли в БД** (`users.role`): `USER`, `ADMIN`, `MODERATOR`. Ролей «Автор» и «Медиа» в БД нет, они есть только в интерфейсе и в продукте.
- **В `SecurityConfig` префикс `/v2/admin/**` уже закрыт ролью ADMIN.** Админские эндпоинты нужно делать под ним.
- **Рецензии** (`reviews.status`): `NOT_WRITTEN` (черновик), `PENDING_MODERATION`, `PUBLISHED`. Уже есть:
  - `GET /v2/reviews/moderation?limit&offset` — очередь, только ADMIN, старые сначала;
  - `POST /v2/reviews/{id}/publish` — опубликовать, только ADMIN.

  Отклонения нет, статуса `REJECTED` нет, флага спойлера в БД нет (фронт его шлёт, бэкенд игнорирует).
- **`ReviewResponse`:** `reviewId, userId, media{tmdbId,title,posterUrl,director}, rating{parameters, finalScore}, title, content, likes, status, createdAt, publishedAt`. Ника автора в ответе нет — его берём из `GET /v1/users/{userId}`.
- **Параметры оценки:** `dramaturgy_structure`, `characters_performance`, `visual_language`, `sound_music` (качество) и `impression` (впечатление), каждый 1–10. Итог 0–100 считает бэкенд.
- **Пользователи:** `users.is_active` есть (блокировка возможна), полей «проверен модератором» нет. Регистрация мгновенная, без проверки.
- **Авторы (создатели фильмов):** фронт шлёт заявку `POST /v1/author/apply {login,password,name,specialty}`, но на бэкенде этого нет. Верификацию автора делает команда вручную.
- **Правила публикации рецензий** (в форме на сайте): от 150 до 10 000 символов; без оскорблений и нецензурной лексики; спойлеры обязательно отмечаются. Рецензию пользователь не редактирует и не удаляет после публикации.
- **Аналитика v10.40:** бэкенд должен писать события `review_published`, `review_rejected`, `review_removed`, `role_assigned`. Панель — главный источник этих действий.
- **Стиль сайта:** тёмная тема, Inter, токены `--bg #070912`, `--surface #101421`, `--surface2 #151a29`, `--line rgba(255,255,255,.09)`, акцент `#8f74ff`, авторский цвет — оранжевый `#ffad61`, радиусы ×0,75 (8–12 px). Без градиентов на кнопках.

## Что сделать

Одна статическая страница: `index.html` + `admin.js` + `admin.css`, без сборки и зависимостей.
- Раздаётся с того же домена по пути `/admin/`, поэтому API доступен на `/api` без CORS.
- Адрес API задаётся в `config.js`.
- Без адреса API (или с `?demo`) панель работает на демо-данных, чтобы её можно было показать и проверить до готовности бэкенда.

### Разделы

1. **Обзор.** Счётчики: рецензий в очереди, новых пользователей на проверке, заявок авторов. Сколько опубликовано и отклонено за 7 дней. Самая старая рецензия в очереди: сколько часов она ждёт. Быстрые переходы к очередям.
2. **Рецензии.** Вкладки «Очередь / Опубликованные / Отклонённые».
   - Карточка рецензии:
     - фильм с постером;
     - ник автора рецензии и дата его регистрации (новичок ли он);
     - оценка по 5 параметрам и итог;
     - заголовок и полный текст;
     - счётчик символов с проверкой 150–10 000;
     - подсветка мата и оскорблений по словарю: подсказка модератору, а не автоматическое решение.
   - Действия: «Опубликовать», «Отклонить» с обязательной причиной из списка (короче 150 знаков, оскорбления, нецензурная лексика, неотмеченные спойлеры, не о фильме, спам или реклама, другое + комментарий), «Снять с публикации» для опубликованных.
   - Горячие клавиши для очереди: `A` — опубликовать, `R` — отклонить, `J/K` — следующая/предыдущая.
3. **Пользователи.** Вкладки «Новые / Проверенные / Заблокированные».
   - Карточка пользователя:
     - ник, дата регистрации, роль;
     - активность (оценки, рецензии, лайки);
     - био и аватар;
     - последние рецензии.
   - Действия:
     - «Проверен» — убрать из очереди новых;
     - «Сменить ник» — для оскорбительных ников;
     - «Заблокировать / Разблокировать» с причиной;
     - «Медиа» — включить или выключить бейдж;
     - роль `MODERATOR` — только для ADMIN.
4. **Авторы.** Вкладки «Заявки / Верифицированные / Отклонённые».
   - Карточка заявки:
     - имя, специальность, логин;
     - ссылки на подтверждение: портфолио, Кинопоиск, соцсети;
     - дата подачи.
   - Действия:
     - «Верифицировать» — с выбором фильмов, к которым привязан автор;
     - «Отклонить» с причиной;
     - «Запросить подтверждение» — комментарий для связи.
5. **Журнал действий.** Кто, что, над чем и когда: публикации, отклонения, блокировки, верификации. Нужен, чтобы в команде из 2–3 модераторов было видно, кто принял решение.

### Поведение

- **Вход.** Логин и пароль аккаунта с ролью ADMIN или MODERATOR. Обычный пользователь получает понятный отказ. Токен хранится в `sessionStorage`, отдельно от токена сайта.
- **Каждый раздел работает независимо.** Если бэкенд ещё не реализовал эндпоинт (404/501), раздел показывает «Ещё не подключено на бэкенде: `METHOD /path`», а не ломает панель. Уже сейчас должны работать очередь рецензий и публикация.
- **Состояния:** загрузка, пусто («Очередь пуста»), ошибка с повтором. Действия с подтверждением там, где они необратимы (блокировка, снятие с публикации).
- **Доступность:** контраст 4,5:1, фокус виден, области нажатия ≥ 24 px, статус не передаётся только цветом.
- **Ширина:** desktop-first (модерация идёт с ноутбука), но без поломок до 375 px.

## Не делать

- **Управление контентом фильмов** — фильмы приходят из TMDB.
- **Управление партнёрами** — по решению «не расширять функционал до проверки гипотезы».
- **Аналитику** — она в Яндекс Метрике и внутренних событиях.
- **Регистрацию модераторов из панели** — роль выдаёт только ADMIN.
- **Хранение паролей и персональных данных** — в памяти браузера дольше сессии.
