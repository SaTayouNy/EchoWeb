# Эхо — что сделать бэкенду (frontend-v10.34)

Актуальный контракт — `API_LIVE.md` и `src/echo-api.js`. Файлы `BACKEND.md` и `API.md` описывают старую схему (cookie, `/movies`, `/auth/me`) и **устарели**; правило «автор не ставит обычные лайки» в них тоже устарело.

## 1. Обновить интеграцию (по порядку)

1. **Заменить фронт.** В репозитории бэкенда содержимое `frontend/` заменить папкой `frontend-v10.34/` (без `node_modules/`). Затем `docker compose up --build -d web` или, для готовой статики, взять `dist/` (собран с `VITE_API_URL=/api`). `src/echo-api.js` и пути запросов не менялись.
2. **Обычные лайки от автора** — см. задачу B-9 в разделе 5.
3. **Баллы статуса** (если считаете на сервере): `givenLikes×5 + receivedLikes×10 + ratings×50 + reviews×250 + authorLikesReceived×1000`.
4. **Профиль** (`/v1/me/profile`, `/v1/users/{id}/profile`):
   - `statistics.givenLikes` обязателен, иначе баллы за лайки не считаются;
   - в `ratings[]` нужны пять параметров (`parameters`, `rating.parameters` или `ratingParameters`) с кодами `dramaturgy_structure`, `characters_performance`, `visual_language`, `sound_music`, `impression`, иначе в профиле виден только итог.
5. **`GET /v1/site/movies/{tmdbId}/scores`.** Нужны три группы `reviews`, `ratings`, `critics`, у каждой `total` и `parts` (5 чисел в порядке: драматургия, персонажи, визуал, звук, впечатление), плюс `ratingsCount`. Если групп или `parts` нет — блок показывает «—» без параметров. Из этих же данных строятся оценки в Эхо Studio и средние оценки работ автора.
6. **Рецензии** (`/v2/reviews`, `/v2/reviews/mine`): поля `userId`, `status` (`PENDING_MODERATION` / `PUBLISHED` / `REJECTED`), `rating.parameters` и `likes`. У собственной отклонённой рецензии нужен `REJECTED`.
7. **Автор:** `GET /v1/author/me` отдаёт объект с `name`; ответ `POST /v1/author/apply` может быть любым (интерфейс всегда показывает успех заявки, ошибку — сообщением).

## 2. nginx и сеть

- `try_files $uri $uri/ /index.html` — SPA, адреса страниц не меняются.
- `location /api/` → Spring без префикса `/api`; `location /tmdb-images/` → `image.tmdb.org/t/p/` (только `w500/*.jpg|png|webp`).
- `client_max_body_size` ≥ 3m (аватар приходит как `dataUrl`).
- Отдельный origin вместо общего адреса: `APP_CORS_ALLOWED_ORIGINS`.
- Формат ошибок: `{error:{code,message,details}}`, `message` на русском (`401`, `409 USERNAME_TAKEN`, `422 VALIDATION_ERROR`).

## 3. Проверить после выкладки

1. Регистрация, занятый логин (`409`), вход, выход, обновление токена по `401`.
2. Оценка без рецензии → итог и пять параметров в профиле.
3. Рецензия → `PENDING_MODERATION` видна автору в «Моё», после модерации — всем.
4. Лайк рецензии зрителем и автором; повторный клик снимает лайк; при ошибке сервера интерфейс откатывает лайк сам.
5. Авторский лайк и авторский комментарий в Эхо Studio, лайк комментария.
6. Карточка фильма: три блока оценок с параметрами; мини-карточки в каталоге, поиске, фильмографии.
7. Перезагрузка на любой странице → главная (без 404); постеры грузятся через `/tmdb-images/`.

## 4. Решения, которые нужны от бэкенда (по контракту «Расхождения»)

| Что | Решение | Оценка |
|---|---|---|
| Единый запрос страницы фильма | подключить `GET /v2/media/movie/{id}/details` вместо трёх запросов (фронт переключу по готовности) | 0,5 дня |
| Публичный список пользователей и топ-5 | paginated endpoint; сейчас профили берутся только у авторов видимых рецензий | 0,5–1 день |
| Каталог работ авторов | endpoint; сейчас работы собираются из титров загруженных фильмов | 1–2 дня |
| Почта и восстановление пароля | выбрать SMTP-провайдера; в UI только логин и пароль | 1–2 дня |
| Домен и HTTPS | до включения публичного входа; на IP-адресе только демо-аккаунты | — |
| Баллы статуса | считает сервер или фронт (см. п. 1.3) | — |

## 5. Доработки бэкенда (от 30.10.2026)

Приоритет: **P1** — блокирует корректное отображение, **P2** — нужно до релиза.

| № | Приоритет | Проблема | Что сделать на бэкенде | Затронутые запросы |
|---|---|---|---|---|
| B-1 | P1 | В мини-карточках фильма (каталог, поиск, фильмография) пустое поле «Режиссёр»: в элементах списков нет режиссёра, коннектор подставляет `director: ''` | Добавить `director` (строка; при нескольких — через запятую) в каждый элемент `items[]` | `GET /v1/media/discover/movies`, `/discover/movies/popular`, `/search/movies` |

Ответ ≤ 300 мс, мин. длина запроса 2 символа. Фронт переведёт поле на живой поиск с задержкой 300 мс | новый `/v1/media/search/people`, `/v1/media/search/movies` |
| B-7 | P1 | Страны приходят на английском (`United States of America`) | Отдавать названия стран на русском (запрос к TMDB с `language=ru-RU` или словарь ISO 3166-1 → рус.). Фильтр каталога по-прежнему принимает ISO-код | `/v1/media/MOVIE/{id}` (`countries`), `/v2/media/movie/{id}/details` |
| B-8 | P1 | «Популярное сейчас» = подборка TMDB, не отражает активность на Эхо | Отдавать 5 фильмов с наибольшим числом оценок (с рецензией и без) за последние 7 дней; при равенстве — по числу рецензий, затем по дате последней оценки; если фильмов меньше 5 — добирать из TMDB popular. Кэш 10–15 мин | `GET /v1/media/discover/movies/popular?period=week&limit=5` (или новый `/v1/site/movies/trending`) |
| B-9 | P1 | Автор не может поставить обычный лайк: запросы принимают только токен зрителя | Принимать токен роли `AUTHOR` в запросах обычных лайков. Для автора `likedByMe` и `/v1/site/me/review-likes` — его собственные обычные лайки; в `likes` они учитываются, в «лайки автора» (`/v1/author/review-likes`) не попадают и в профиле автора не показываются | `PUT/DELETE /v2/reviews/{id}/like`, `PUT/DELETE /v1/author/movies/{tmdbId}/comment/like`, `GET /v1/site/me/review-likes` |

**Критерий готовности по каждой задаче:** запрос описан в `API_LIVE.md` и Swagger, на тестовом стенде возвращает данные в указанном формате, ошибки — в формате `{error:{code,message,details}}`. После B-4, B-5, B-6 и B-8 нужна доработка коннектора `src/echo-api.js` — сообщите о готовности, фронт подключит.
