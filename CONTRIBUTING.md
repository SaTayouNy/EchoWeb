# Как работать с репозиторием

> Для разработчиков и всех, кто вносит изменения в код или wiki «Эхо».

## 1. Доступ
1. Создайте аккаунт на GitHub и сообщите логин PM.
2. PM добавит вас в **Collaborators** репозитория (Settings → Collaborators) — придёт приглашение на почту, его нужно принять.
3. Без доступа можно предлагать изменения через fork и pull request.

## 2. Запуск
```bash
git clone https://github.com/SaTayouNy/EchoWeb.git
cd EchoWeb
git checkout develop
npm install
npm run dev          # http://localhost:5173, демо-данные
```
С локальным бэкендом, Windows и подробности — в [разделе разработки](docs/04-development/README.md).

## 3. Ветки

| Ветка | Назначение | Кто пишет |
|---|---|---|
| `main` | Продакшен и опубликованная wiki. Каждый релиз — тег `vX.Y.Z` | Только через PR, ревью PM |
| `develop` | Интеграция: сюда сливаются все задачи; выкладывается на staging | Через PR, ревью коллеги |
| `feature/<номер-issue>-<кратко>` | Новая функция, например `feature/14-mobile-stub` | Исполнитель задачи |
| `fix/<номер-issue>-<кратко>` | Исправление бага | Исполнитель |
| `docs/<тема>` | Изменения wiki в `docs/` | Любой участник |

```bash
git checkout develop && git pull
git checkout -b feature/14-mobile-stub
# … работа …
git push -u origin feature/14-mobile-stub
```

## 4. Pull request
- Код — PR в **`develop`**. Только wiki (`docs/`) — PR в **`main`**, чтобы изменения сразу были видны.
- В описании — `Closes #номер` задачи и как проверить; чек-лист заполняется по шаблону.
- Нужен минимум один **Approve**: FE ↔ BE друг у друга, wiki и регламенты — PM.
- Перед PR подтяните свежий `develop` (`git pull origin develop`) и решите конфликты у себя.
- После слияния ветку удалите.

**Релиз:** PR `develop` → `main` → тег `vX.Y.Z` → выкладка по [инструкции](docs/04-development/deploy.md).

## 5. Коммиты
Коротко и по делу, в повелительном наклонении: `Добавить заглушку для телефонов (#14)`, `Исправить откат лайка при ошибке (#21)`. Один коммит — одно логическое изменение.

## 6. Правила кода
- Обмен с сервером — **только в `src/api.js`**. Формат данных для интерфейса — в функции `normalize` там же.
- Никаких секретов в репозитории: `.env`, ключи, пароли, токены, личные телефоны и почты, ссылки-приглашения в рабочие чаты. Репозиторий **публичный**. Шаблон настроек — `.env.example`.
- Новые зависимости — только по согласованию с командой.
- Изменилось поведение продукта — обновите страницу wiki в том же PR.

## 7. Задачи
Задачи, баги и запросы на изменения — в [Issues](https://github.com/SaTayouNy/EchoWeb/issues/new/choose) по шаблонам. Статусы и метки — в [регламенте задач](docs/02-management/task-workflow.md), изменения требований — в [регламенте изменений](docs/02-management/change-management.md).
