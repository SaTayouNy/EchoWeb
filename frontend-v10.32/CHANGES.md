## Как заменить фронт на хосте

1. В репозитории бэкенда замените содержимое папки `frontend/` содержимым этой папки. `node_modules/` не копируйте.
2. Пересоберите контейнер: `docker compose up --build -d web`. Dockerfile сам соберёт фронт с `VITE_API_URL=/api`.
3. Или, если выкладываете готовую статику (`compose.prebuilt.yaml`), возьмите папку `dist/`: она уже собрана с `VITE_API_URL=/api`.
4. Проверьте в браузере: главная, каталог, страница фильма, вход, профиль, отправка рецензии.

`nginx.conf`, `Dockerfile`, лендинги в `public/authors/` и контракт `API_LIVE.md` не менялись.

## Изменения в коннекторе `src/echo-api.js` — для бэкенда

Пути запросов не менялись. Изменена только обработка ответов:

1. **Баллы статуса** считаются по утверждённой таблице (`POINT_VALUES`, `pointsFromStats`): `givenLikes×5 + receivedLikes×10 + ratings×50 + reviews×250 + authorLikesReceived×1000`. Раньше было 100/10/3/500. Если бэкенд считает баллы сам, нужны те же значения.
2. **Параметры оценок в профиле.** Читаются из `ratings[].parameters`, `ratings[].rating.parameters` или `ratings[].ratingParameters` (коды `dramaturgy_structure`, `characters_performance`, `visual_language`, `sound_music`, `impression`). Если бэкенд их не отдаёт в `/v1/me/profile` и `/v1/users/{id}/profile`, в профиле будет виден только итог.
3. **Рецензии** получили поля `userId`, `points` (баллы автора рецензии — для статуса) и `moderation` (исходный `status`: `PENDING_MODERATION`, `PUBLISHED`, `REJECTED`).
4. **`saveRating`** возвращает ответ `PUT /v2/me/ratings/...`: оттуда берётся `finalScore`.
5. **Фильмы с авторскими комментариями** подгружаются при старте, даже если их нет среди популярных. Так комментарий в профиле автора всегда показывается вместе с фильмом.

## Что проверить на бэкенде

- `statistics` в профиле содержит `givenLikes`. Без него баллы за поставленные лайки не учитываются.
- Ответ `POST /v1/author/apply` может быть любым: интерфейс всегда показывает экран успешной заявки, ошибки — сообщением.
- `GET /v1/author/me` возвращает объект с `name`.
- Статус `REJECTED` у собственной рецензии отдаётся в `/v2/reviews/mine`. Тогда интерфейс покажет «Отклонена модератором».

## Как проверено

- Режимы: с API (через локальный мок-сервер по контракту `API_LIVE.md` — сам тестовый стенд из рабочего окружения недоступен) и на демо-данных.
- Сценарии: регистрация (в том числе занятый логин), вход по Enter, профиль, топ-5, оценка без рецензии, рецензия и её модерация, лайк гостем → вход, каталог с фильтрами, поиск, профили авторов (подтверждённый и из титров), заявка автора, вход автора, Эхо Studio, перезагрузка с черновиком и с сессией автора.
- Разметка: 1440, 1100, 1024, 768 и 390 px — без горизонтальной прокрутки. Совпадение высот пустого и заполненного топ-5 и одинаковая высота мини-карточек проверены измерением.
- Консоль: ошибок скриптов нет.
