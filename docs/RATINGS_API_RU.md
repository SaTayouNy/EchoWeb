# Система оценок — API v2

Все изменения выполняются от имени владельца Bearer-токена. Идентификатор другого пользователя в URL или теле записи не принимается. Для чтения схем, списков пользователя и агрегатов авторизация не требуется. Swagger UI: `/swagger-ui/index.html`, OpenAPI: `/v3/api-docs`.

## Параметры и формула

`GET /v2/rating-schemes/current` возвращает текущую схему `echo-form-impression-v1`, формулу, правила округления и описания пяти параметров для onboarding. `GET /v2/rating-schemes/{version}` возвращает конкретную версию, включая старые.

| Код | Название | Роль |
| --- | --- | --- |
| `dramaturgy_structure` | Драматургия и структура | Форма |
| `characters_performance` | Персонажи и исполнение | Форма |
| `visual_language` | Визуальный язык | Форма |
| `sound_music` | Звук и музыка | Форма |
| `impression` | Впечатление | Личное впечатление |

Каждый параметр — целое число от 1 до 10, шаг 1. Строки, дробные JSON-числа (в том числе `9.0`), null, пропущенные и неизвестные параметры отклоняются.

```
formQuality = (dramaturgy_structure + characters_performance + visual_language + sound_music) / 4
baseScore = formQuality * 10
impressionMultiplier = 0.4 + 0.6 * (impression - 1) / 9
finalScore = round(baseScore * impressionMultiplier)
```

Округление итогового балла — HALF_UP, то есть точные половины округляются вверх. Итог ограничен 100. Минимальный результат — 4/100, максимальный — 100/100. Множитель в JSON показывается с точностью до 12 десятичных знаков; расчёт итогового балла использует точное рациональное значение без промежуточного округления. Значения `9 / 8 / 7 / 9 / 9` дают `8.25`, `82.5`, `0.933333333333`, **77**.

## Создание и изменение

`PUT /v2/me/ratings/movie/{tmdbId}` создаёт или полностью заменяет оценки параметров текущего пользователя. Повторная отправка тех же значений сохраняет `ratingId` и обе даты. Поддерживается также `tv` для общей модели релизов.

```json
{
  "schemeVersion": "echo-form-impression-v1",
  "parameters": {
    "dramaturgy_structure": 9,
    "characters_performance": 8,
    "visual_language": 7,
    "sound_music": 9,
    "impression": 9
  }
}
```

Успешный ответ `200` содержит `ratingId`, `userId`, `mediaType`, `tmdbId`, `title`, `posterPath`, `schemeVersion`, исходный объект `parameters`, `formQuality`, `baseScore`, `impressionMultiplier`, `finalScore`, `createdAt`, `updatedAt`. FE не передаёт итоговую оценку. Метаданные фильма получаются через существующий TMDB-кеш; при ошибке загрузки новая оценка не записывается.

`GET /v2/me/ratings/movie/{tmdbId}` получает собственную оценку. `DELETE` по тому же адресу возвращает `204` и идемпотентен. При наличии связанной рецензии удаление оценки запрещено (`409 RATING_IN_USE`): сначала удаляется рецензия. Изменение исходных оценок опубликованной рецензии возвращает её на модерацию; повторный PUT без изменений не меняет статус.

## Списки и агрегаты

- `GET /v2/users/{userId}/ratings?page=0&size=20`: структурированные оценки пользователя, сортировка по `updatedAt DESC, ratingId DESC`, `items` и `meta` (`page`, `size`, `total`, `totalPages`). `size` — 1–100.
- `GET /v2/media/movie/{tmdbId}/ratings`: `count` и массив `schemes`. Каждая запись содержит `schemeVersion`, `count`, `parameterAverages` и `averageFinalScore`. Последнее — среднее уже округлённых индивидуальных итоговых оценок; не повторный расчёт по средним параметрам. Средние показываются до 4 знаков. Разные версии формулы никогда не смешиваются. Без оценок возвращается `count: 0`, `schemes: []`.

## Хранение, версии и совместимость

Миграция V15 создаёт `rating_schemes`, `rating_parameters`, `user_rating_values` и расширяет `user_ratings`. Пять исходных значений хранятся отдельно от кеша `final_score`; связь пользователя с релизом остаётся уникальной. Записи сохраняются после выхода, повторного входа и перезапуска БД.

Опубликованные параметры и формула версии неизменяемы. Для смены состава параметров или формулы добавляется новая версия и реализация её `formulaCode`, затем активируется новая версия. Ранее созданные оценки продолжают ссылаться на исходную схему и редактируются в ней, даже если она больше не активна; смена версии существующей записи запрещена (`409 RATING_SCHEME_CONFLICT`). Это сохраняет смысл и исходные значения исторических оценок. Автоматического переноса старых оценок на новую формулу нет.

Старые скалярные значения 1–10 сохраняются без вымышленных пяти параметров. При первом PUT v2 исходный скаляр остаётся в БД, а рейтинг получает структуру и версию. Созданный через v2 рейтинг не имеет скалярной оценки. Старые GET v1 поддерживают имеющиеся данные; PUT/DELETE v1 не могут перезаписать или удалить структурированную оценку (`409 STRUCTURED_RATING_REQUIRES_V2`). Скалярные оценки исключены из агрегатов v2.

## Ошибки

- `400`: некорректный JSON или тип значения.
- `401`: отсутствующий, истёкший или отозванный токен.
- `404 STRUCTURED_RATING_NOT_FOUND`: у пользователя ещё нет структурированной оценки; `404 NOT_FOUND` — неизвестный пользователь в списке.
- `409`: конфликт версии, попытка записи по неактивной схеме, изменение структуры через v1 или удаление оценки со связанной рецензией.
- `422 VALIDATION_ERROR`: диапазон, отсутствующий/лишний параметр, неверные параметры пагинации; `422 RATING_SCHEME_NOT_FOUND` — неизвестная версия.
- `503 RATING_SCHEME_NOT_CONFIGURED`: активная схема не настроена однозначно либо отсутствует реализация формулы. Ошибки TMDB используют существующий контракт сервиса.

Тесты: `RatingCalculatorTest`, `StructuredRatingIntegrationTest`, `StructuredRatingMigrationTest`; интеграцию с публикацией и модерацией проверяют тесты рецензий.
