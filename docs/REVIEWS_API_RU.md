# API рецензий v2

Новые рецензии используют пять сохранённых параметров из [API оценок](RATINGS_API_RU.md). Произвольный итоговый балл API рецензий не принимает и не использует. Автор сначала сохраняет оценку для своего фильма, затем создаёт рецензию. Публикация выполняется администратором после модерации. Авторизация: `Authorization: Bearer <accessToken>`.

## Жизненный цикл

`NOT_WRITTEN` — сохранённый незавершённый черновик; заголовок и содержание могут быть пустыми. `PENDING_MODERATION` — отправленная на проверку рецензия. `PUBLISHED` — опубликованная администратором рецензия.

Создание/изменение с `draft: true` сохраняет черновик. `draft: false` отправляет заполненную рецензию на модерацию. При изменении опубликованного заголовка, содержания или параметров связанной оценки публикация снимается; требуется повторное одобрение администратора. Повторная отправка идентичных данных сохраняет публикацию. `publishedAt` хранит дату текущей публикации, до одобрения равен `null`. `createdAt` и `updatedAt` хранят даты создания и изменения.

В БД одна рецензия на `(user_id, media_type, tmdb_movie_id)`, включая черновики. Повторное создание возвращает `409`; для изменений используется PUT. Удаление физическое: удаляются также лайки и ответы, оценка сохраняется. После удаления можно создать новую рецензию. Удалить связанную оценку можно только после удаления рецензии.

## Запросы

| Метод и путь | Назначение |
|---|---|
| `POST /v2/reviews` | Создать черновик или отправить рецензию на проверку |
| `PUT /v2/reviews/{reviewId}` | Заменить заголовок/содержание своей рецензии |
| `DELETE /v2/reviews/{reviewId}` | Удалить свою рецензию |
| `GET /v2/reviews/{reviewId}` | Получить рецензию |
| `GET /v2/reviews` | Публичный список опубликованных рецензий |
| `GET /v2/reviews/mine` | Все собственные рецензии, включая черновики |
| `GET /v2/reviews/moderation` | Очередь ожидающих модерации, только ADMIN |
| `POST /v2/reviews/{reviewId}/publish` | Опубликовать ожидающую модерации рецензию, только ADMIN |
| `PUT /v2/reviews/{reviewId}/like` | Идемпотентно поставить лайк опубликованной рецензии |
| `DELETE /v2/reviews/{reviewId}/like` | Идемпотентно убрать свой лайк |

Создание:

```json
{
  "tmdbId": 550,
  "mediaType": "MOVIE",
  "title": "История и форма",
  "content": "Разбор фильма.\nВторая строка.",
  "draft": false
}
```

PUT принимает только `title`, `content`, `draft`. Фильм и автор неизменяемы; статус `PUBLISHED` и итоговый балл нельзя назначить через тело запроса. Для непустой рецензии длина заголовка 1–200, содержания 1–10 000 символов; внешние пробелы удаляются. Переносы строк и табуляция разрешены в содержании. Управляющие символы запрещены; заголовок однострочный. Отсутствующее значение `draft` эквивалентно `false`.

## Списки и ответ

Публичный список: необязательные `tmdbId`, `mediaType`, `userId`; `limit` от 1 до 100 (по умолчанию 20), `offset` от 0. `sort`: `createdAt`, `publishedAt` (по умолчанию), `rating`, `likes`; `order`: `asc`/`desc` (по умолчанию `desc`). При равенстве основного значения используется стабильный порядок по ID. `mine` поддерживает `status`, те же параметры пагинации/сортировки; сортировка по умолчанию `createdAt`. Очередь модерации поддерживает `limit`/`offset`, сортируется по созданию от старых к новым. Ответ списка: `{ "items": [...], "meta": { "limit": 20, "offset": 0, "total": 1 } }`.

Рецензия содержит `reviewId`, `userId`, затем `media` (постер, название, режиссёр), `rating` (пять исходных параметров, схема, вычисленные показатели и `finalScore`), `legacyRating`, `title`, `content`, `likes`, `publishedAt`, `status`, `createdAt`, `updatedAt`. Вложенного блока профиля автора нет. Метаданные фильма берутся из каталога; у ещё не синхронизированного фильма постер/режиссёр могут быть `null`. Изменения оценок читаются через ту же связанную запись, отдельной копии параметров в рецензии нет. Лайки считаются по `review_likes`; одному пользователю доступен один лайк чужой рецензии.

Неопубликованная рецензия по ID доступна автору и ADMIN, остальным возвращается `404`. Публичные списки, старые v1-списки, профили, ответы и постановка лайков не раскрывают неопубликованные рецензии. Чужие изменения/удаления — `403`. Отсутствие авторизации — `401`, ошибка полей — `422`, дубликат/отсутствие структурированной оценки/публикация неподходящего статуса — `409`.

## Совместимость и БД

Миграция V16 сохраняет исторические публикации, связывает их с исходными скалярными оценками (восстанавливает отсутствующие записи из старой рецензии). Исторические рецензии возвращают `rating: null` и `legacyRating` 1–10; пять параметров не выдумываются. После сохранения пяти параметров существующую рецензию можно обновить через v2 и отправить на проверку. POST/PATCH `/v1/reviews` возвращают `409 LEGACY_REVIEW_WRITE_DISABLED`; старый API чтения и удаления сохранён. Связь с оценкой обязательна; уникальность и внешние ключи обеспечиваются БД. Записи одного автора сериализуются блокировкой пользователя.

Swagger/OpenAPI описывает новые пути, модели и Bearer-авторизацию. Документация доступна через настроенные в приложении Swagger UI и `/v3/api-docs`.
