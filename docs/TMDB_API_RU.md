# TMDB API backend

Актуально на 24 сентября 2026. Источник требований к карточке: «Актуальные требования к продукту.pdf», разделы 7–9 и 18–20. Внешний TMDB вызывается только backend; клиент получает JSON и URL изображений. Все маршруты ниже публичные, кроме ручной синхронизации (роль ADMIN).

## Маршруты

| Метод | URL | Параметры | Назначение |
| --- | --- | --- | --- |
| GET | `/v1/media/discover/movies/popular` | `page=1` | Список популярных фильмов |
| GET | `/v1/media/discover/tv/popular` | `page=1` | Список популярных сериалов |
| GET | `/v1/media/discover/movies/trending` | `page=1`, `window=day\|week` | Тренды фильмов |
| GET | `/v1/media/discover/tv/trending` | `page=1`, `window=day\|week` | Тренды сериалов |
| GET | `/v1/media/search/movies` | `query` (обязателен), `page=1` | Поиск фильмов |
| GET | `/v1/media/search/tv` | `query` (обязателен), `page=1` | Поиск сериалов |
| GET | `/v1/media/{mediaType}/{tmdbId}` | `mediaType=MOVIE\|TV`, `tmdbId>0` | Полная карточка |
| GET | `/v1/media/movie/{tmdbId}/recommendations` | `page=1` | Похожие фильмы |
| GET | `/v1/media/tv/{tmdbId}/recommendations` | `page=1` | Похожие сериалы |
| POST | `/v1/media/{mediaType}/{tmdbId}/sync` | Bearer ADMIN | Принудительное обновление карточки |

`page` начинается с 1, максимальное значение 1000. Для поиска `query` непустой и не длиннее 200 символов. `mediaType` регистронезависим. Сервер возвращает `400` для неизвестного значения enum и `422` для нарушения числовых/текстовых ограничений.

## Список и поиск

Все списки используют одну форму:

```json
{
  "items": [
    {
      "mediaType": "MOVIE",
      "tmdbId": 603,
      "title": "Матрица",
      "originalTitle": "The Matrix",
      "overview": "Описание",
      "releaseYear": 1999,
      "releaseDate": "1999-03-31",
      "posterPath": "/poster.jpg",
      "posterUrl": "https://image.tmdb.org/t/p/w500/poster.jpg",
      "genres": ["Action", "Science Fiction"],
      "rating": 8.2
    }
  ],
  "page": 1,
  "totalPages": 1,
  "totalResults": 1
}
```

`rating` в списке — средняя оценка **TMDB**, а не пользователей платформы. Пустой результат — `200` с `items: []`. В поисковой выдаче TMDB нет режиссёра, актёров, стран и внутренних счётчиков рецензий/оценок; FE должен получать режиссёра и страну из полной карточки, а показатели сообщества — из внутренних API. Массовая загрузка полной карточки для каждой строки списка не выполняется, чтобы не создавать десятки запросов к TMDB на открытие одной страницы.

## Полная карточка

`GET /v1/media/MOVIE/603` и `GET /v1/media/TV/{id}` возвращают одинаковую структуру: `mediaId`, `mediaType`, `tmdbId`, `title`, `originalTitle`, `overview`, `originalOverview`, `releaseYear`, `releaseDate`, `runtimeMinutes`, `posterPath`, `posterUrl`, `director`, `cast`, `castDetails`, `crewDetails`, `genres`, `countries`, `lastSyncedAt`, `createdAt`, `updatedAt`.

`cast` — прежний список имён для совместимости. `castDetails` и `crewDetails` — массивы объектов `{tmdbPersonId, name, role, profilePath, profileUrl}`. У актёра `role` — персонаж, у участника группы — должность. `profileUrl` и `posterUrl` — готовые ссылки на CDN TMDB. Если у участника нет фотографии, оба поля профиля равны `null`. В ответе не больше настроенного `app.tmdb.cast-limit` актёров (по умолчанию 15) и 30 участников группы. Режиссёр также доступен в отдельном поле `director`.

Карточка кэшируется в таблице `media`. Повторное открытие синхронизированной карточки читает БД без нового вызова TMDB. Миграция V13 добавляет поля участников и сохраняет прежние карточки; для записей, созданных до V13, новые массивы пусты до очередного обновления TMDB. Если дополнительный запрос за описанием на языке оригинала не удался, backend сохраняет доступное локализованное описание.

Фотографии и постеры не хранятся на сервере: URL строится из `profile_path`/`poster_path`, а фактическую загрузку выполняет клиент с CDN. Доступность CDN должна быть проверена из браузера целевого окружения.

## Ошибки

Форма ошибки: `{ "error": { "code": "...", "message": "...", "details": [...] } }`. Поле `details` присутствует при ошибках валидации.

| Ситуация | HTTP | `error.code` |
| --- | ---: | --- |
| Релиз не найден в TMDB (`404`) | 404 | `MEDIA_NOT_FOUND` |
| Неверный ключ TMDB (`401/403`) | 502 | `TMDB_AUTH_FAILED` |
| Лимит TMDB (`429`) | 503 | `TMDB_RATE_LIMITED` |
| Сбой TMDB (`5xx`), таймаут, отсутствие сети | 502 | `TMDB_UNAVAILABLE` |
| Невалидный JSON, пустой или неполный ответ | 502 | `TMDB_BAD_RESPONSE` |
| Неверные параметры нашего API | 400/422 | `BAD_REQUEST` / `VALIDATION_ERROR` |

Временные ошибки TMDB повторяются не более `app.tmdb.retry-max-attempts` раз (по умолчанию 2). Неверный ключ, отсутствие релиза и некорректный ответ не повторяются. Сбой TMDB не удаляет уже синхронизированную карточку и не отменяет создание рецензии: рецензия может использовать временную запись фильма до успешной синхронизации.

## Проверка и ограничения

Локальные тесты проверяют JSON, преобразование movie/TV, сохранение фотографий участников в БД, повторное чтение, `404`, `401/403`, `429`, `5xx`, таймаут и невалидный успешный ответ. На 24 сентября 2026 переменная `APP_TMDB_ACCESS_TOKEN` не задана; прямое соединение из этой среды с `api.themoviedb.org:443` не установилось (`HTTP 000`). Поэтому реальное содержимое TMDB и доступность его CDN из целевого стенда остаются внешним приёмочным шагом.

Для стенда задайте `APP_TMDB_PROVIDER=http`, `APP_TMDB_ACCESS_TOKEN`, доступ к `api.themoviedb.org:443`, затем проверьте movie, TV, поиск, список и холодное/повторное открытие карточки. Для автономной разработки используйте `APP_TMDB_PROVIDER=stub`.
