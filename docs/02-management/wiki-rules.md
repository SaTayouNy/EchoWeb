# Правила работы с Wiki

> **Цель:** сохранить wiki единственным актуальным источником информации о проекте · **Обновлено:** 23.10.2026 · **Ответственный:** Роман Стяжкин (PM)

Wiki проекта — папка [`docs/`](../README.md) в репозитории EchoWeb. Здесь:
- фиксируются принятые решения;
- хранится проектная документация;
- описываются требования, процессы и договорённости;
- обеспечивается прозрачность работы команды.

**При спорах источником правды является wiki.**

## Зачем

- единое понимание проекта у всей команды;
- меньше устных договорённостей;
- быстрое погружение новых участников и партнёров;
- история версий: GitHub хранит каждое изменение каждой страницы;
- целостность продукта.

## Как вносить изменения

- Каждый участник может менять документы **в своей зоне ответственности**.
- Изменения ключевых разделов (требования, бизнес-логика, регламенты) — только по согласованию с PM.
- Способ:
  1. **Через pull request** (основной способ): ветка `docs/<тема>` → pull request в `develop` или `main` → одобрение PM. См. [CONTRIBUTING](../../CONTRIBUTING.md).
  2. **Мелкая правка** (опечатка, ссылка, статус) в своей зоне — прямо в веб-интерфейсе GitHub: откройте файл → ✏️ → «Propose changes».

## Формат страницы

Каждая страница начинается со строки:

```
> **Цель:** … · **Обновлено:** ДД.ММ.ГГГГ · **Ответственный:** Имя (роль)
```

Пишите кратко, используйте таблицы и списки. Картинки кладите в `docs/assets/`.

## Когда обновлять

- после принятия решений;
- после завершения спринта;
- при изменении требований.

Устаревшая информация **обновляется** или **переносится в [архив](../archive/README.md)** с пометкой, что её заменило.

## Как фиксировать решения

Любое значимое решение записывается в [лог решений](decisions-log.md):
- что решено;
- почему;
- кто участвовал;
- дата.
