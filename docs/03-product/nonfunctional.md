# Нефункциональные требования

> **Цель:** зафиксировать нефункциональные требования для приёмки продукта · **Обновлено:** 23.10.2026 · **Ответственный:** Роман Стяжкин (PM)

Документ объединяет прежние «Основные требования к продукту» (нефункциональная часть) и «Нефункциональные требования». Где цифры расходились, приняты значения **для MVP** (проверяются в [спринте 7](../07-sprints/sprint-07.md)) и отдельно — **цели масштабирования** на будущее.

## 1. Удобство (UX)
- Интерфейс замедляет, а не подгоняет: стимулирует вдумчивый анализ.
- Без визуального шума, минималистичный дизайн, без агрессивных анимаций и всплывающих окон.
- Логичная навигация; до оценки или рецензии — 1–2 клика со страницы фильма.
- Комфортная типографика для долгого чтения — см. [оформление рецензий](review-design.md).

*Как измерять:* время чтения рецензий и просмотра карточек, число кликов до целевого действия.

## 2. Производительность

| Показатель | MVP (к запуску) | Цель масштабирования |
|---|---|---|
| Загрузка главной | < 3 с | — |
| Загрузка страницы фильма или профиля | < 2 с | — |
| Отклик интерфейса на действие | ≤ 0,5 с | — |
| Поиск | ≤ 3 с | — |
| Ответ API (серверная часть, штатная нагрузка) | 99% запросов < 1 с, целевое < 500 мс | Чтение < 100 мс, запись < 200 мс |
| Одновременная нагрузка | 50–100 пользователей (нагрузочный тест) | 1 000 одновременных запросов; 10 000 активных пользователей |
| Lighthouse (Performance) | ≥ 70 | — |

- Загрузка асинхронная; интерфейс не блокируется во время ожидания ответа.
- Пользователь всегда видит состояние загрузки.
- Повторное открытие данных не вызывает лишних запросов; часто просматриваемые страницы кэшируются.
- Обработка длинных текстов (до 10 000 символов) без задержек.

## 3. Совместимость
- **Устройства:** десктоп, ноутбук, планшет (16:9, 16:10, 4:3), включая смену ориентации. На телефоне — экран-заглушка. Лендинг для авторов адаптирован под телефоны.
- Нет горизонтального скролла; текст читается на всех поддерживаемых разрешениях.
- **Браузеры** (последние стабильные версии): Chrome, Яндекс Браузер, Firefox, Safari, Edge.
- Соблюдение веб-стандартов, без критических различий поведения между браузерами.

*Как измерять:* доля пользователей с проблемами совместимости (по аналитике и обращениям).

## 4. Безопасность
- Только HTTPS (TLS 1.2+).
- Пароли хранятся только в виде хеша (BCrypt); никогда не логируются.
- Пользователь не может получить данные или выполнить действие за другого, подменив ID в запросе.
- Сервер валидирует все входные данные; защита от XSS и SQL-инъекций.
- Сессия ограничена по времени: access-токен 30 минут, refresh-токен 30 дней.
- Ограничение частоты входа и регистрации (rate limiting).
- Верификация авторов и медиа; защита от спама и накрутки.

*Как измерять:* доля заблокированных подозрительных действий, результат проверки безопасности в тестировании.

## 5. Надёжность
- Ежедневное резервное копирование БД, хранение копий не менее 7 дней.
- Автоматический перезапуск бэкенда после сбоя или перезагрузки сервера.
- Без потери созданной рецензии, оценки или предпочтений при ошибках и перезапусках.
- Корректная работа при недоступности TMDB и при ошибках API.
- **RTO** (время восстановления) < 30 минут; **uptime** ≥ 98%.

## 6. Модерация и администрирование
- Удобный просмотр рецензий и регистраций для модератора.
- Быстрое удаление спама; отслеживание подозрительной активности.

*Как измерять:* время реакции модератора, число жалоб на контент.

## 7. Качество данных
- Данные о фильмах и авторах достоверны (источник — TMDB + ручная проверка авторов).
- Рецензии не дублируются и соответствуют правилам платформы.

*Как измерять:* ошибки в карточках фильмов, жалобы на контент.

## 8. Поддерживаемость и масштабируемость
- Новые функции добавляются без переработки существующих.
- Код структурирован и задокументирован, у ключевых функций есть комментарии.
- Общепринятые стандарты разработки; см. [CONTRIBUTING](../../CONTRIBUTING.md).
- Можно подключать новые внешние сервисы.

## 9. Логирование и мониторинг
Фиксируются: ошибки бэкенда, ошибки внешних API, ошибки БД, критические ошибки авторизации, недоступность сервиса. Ошибки фронтенда отслеживаются через аналитику, а после релиза — через Sentry (см. [внешние сервисы](../04-development/external-services.md)).
