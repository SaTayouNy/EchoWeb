# Готовность всего сайта Echo к рабочему запуску

Оценка от 12 сентября 2026 по текущей рабочей копии. Основа — выполненный аудит BE и дополнительное чтение активного FE (`frontend/src/main.tsx` → `App.tsx`). Новые выводы о FE ниже получены по коду; браузерное E2E и проверка production-стенда не выполнялись.

**Общий статус: частично работающее приложение с реализованным основным API. Полный пользовательский путь и эксплуатационная готовность ещё не завершены.** Проект не нужно переписывать целиком. Основная оставшаяся работа — исправить дефекты, подключить существующий API к экранам, реализовать постоянное избранное и завершить запуск на целевой инфраструктуре.

Процент готовности не рассчитывается: нет утверждённого полного списка функций и их трудоёмкости. Наличие экрана, наличие API, успешный локальный тест и подтверждённая работа на стенде — разные уровни готовности. Процент прошедших тестов не является процентом готовности продукта.

## Матрица готовности

| Блок | Что уже есть | Что отсутствует / не подтверждено | Готовность и критичность |
|---|---|---|---|
| Регистрация и вход | BE и FE связаны; username/password работает; пароли хешируются | Исправления занятого логина, длинного пароля и уникальности логина в БД | Основной путь работает; дефекты блокируют приёмку auth |
| Сессия пользователя | BE поддерживает access/refresh, logout, обнаружение повторного refresh | FE не обновляет токены и не проверяет сохранённую сессию при восстановлении страницы | BE в основном готов; клиентский жизненный цикл не завершён |
| Каталог | Экраны и запросы popular/trending movie/TV | Живой TMDB не проверен; случайные страницы объединяются в выборку максимум 40 карточек | Частичная интеграция; полный каталог не готов |
| Поиск и фильтры | Поиск movie/TV; локальная фильтрация | Поиск берёт первую страницу каждого типа и обрезает объединённый результат до 20; нет пагинации. Фильтры применяются к загруженным карточкам, а не всему каталогу. В search DTO нет стран | Частично работает; важно до приёмки поиска |
| Карточка фильма/сериала | BE детали, БД-кэш, FE описание, постер, команда | Живые данные и CDN не проверены; ошибка detail-запроса подавляется, пользователь не видит причину отсутствия деталей | Почти собран основной путь; приёмка зависит от TMDB и обработки ошибок |
| Рецензии | BE CRUD, фильтры по пользователю/фильму, права доступа | В FE нет запросов reviews и форм работы с ними; всегда сообщение «рецензий нет». На BE есть ошибки валидации/PATCH | Серверная основа готова, пользовательская функция не завершена; блокер основного продукта |
| Оценки | BE сохраняет оценку 1–10 в review; в выдаче есть рейтинг TMDB | Нет UI выставления оценки. В профиле счётчик всегда 0. Отдельный агрегат пользовательского рейтинга и оценка без текста не реализованы | Частично на BE; пользовательский путь отсутствует |
| Ответы на рецензии | BE CRUD, проверки владельца | FE не подключён | API готов к подключению; функция в сайте отсутствует |
| Избранное | Кнопки, экран и счётчик | Нет BE API/таблицы; `likedIds` хранится в React state, пропадает после перезагрузки. Выдача зависит от текущего набора карточек. При смене аккаунта state явно не очищается | Только локальная логика интерфейса; для заявленного экрана сайта требуется полноценное сохранение |
| Профиль | Имя/email реального пользователя; BE private/public lookup | Лента рецензий не подключена; счётчики reviews/ratings захардкожены в 0. Нет редактирования профиля/привязки email | Только базовое чтение аккаунта; профиль как раздел не завершён |
| Восстановление доступа | BE email recovery и verification, outbox, тесты | SMTP не проверен; FE reset-password не реализован; аккаунту без email восстановление недоступно | Не завершено; политику восстановления нужно определить до выпуска |
| Навигация | Переключение экранов через React state | Отдельных URL карточки/профиля/избранного в активном приложении нет; не реализованы адресуемые страницы и соответствующая browser history | Работает как один экран с состояниями; требуется маршрутизация для рабочего сайта |
| БД | Миграции, H2 CRUD/каскады/сохранность проверены | Нет Flyway-модуля PostgreSQL; реальная PostgreSQL не проверена | H2 готова локально; PostgreSQL — блокер целевого запуска |
| Развёртывание и эксплуатация | Production-oriented BE config, actuator, сборка FE/BE | В репозитории не найдены инструкции/артефакты полного автоматизированного запуска, backup/restore и release pipeline; готовность внешней инфраструктуры неизвестна | Готовность к эксплуатации не подтверждена |
| Тестирование всего сайта | Локальные BE-тесты и HTTP-аудит; FE build и 15 компонентных тестов | Компонентные тесты не покрывают активный App целиком; нет выполненного browser E2E, проверки мобильных экранов, production origin и восстановления после перезапуска | Основа проверки есть; релизной приёмки нет |

Избранное и реальные данные профиля здесь считаются обязательными, поскольку пользователь видит эти разделы в текущем сайте. Возможность отложить отдельную среднюю оценку, редактирование профиля или другие расширения требует согласования продуктового объёма; они не объявляются автоматически обязательными функциями PM.

## Обязательные работы в порядке зависимости

### 1. Исправить целостность аккаунтов и серверные ошибки

- Возвращать честный конфликт занятого логина вместо фиктивного 201/userId.
- Исправить обработку паролей длиннее 72 UTF-8 байт; обеспечить совместимость существующих аккаунтов.
- Ввести уникальный канонический username на уровне БД с проверкой старых данных.
- Исправить отрицательные/нулевые TMDB ID, дробные оценки, многострочный PATCH, ошибочные 500, обход rate limit через регистр пути.
- Согласовать enum, ошибки, два вида рейтингов и регистрацию с optional email.

Критерий: положительные и отрицательные auth/review сценарии проходят, неверные данные не сохраняются и не возвращают ложный успех. Подробные дефекты и воспроизведение — в `BE_AUDIT_RU.md` и `audit/http-results.json`.

### 2. Получить воспроизводимый рабочий стенд

- Добавить модуль Flyway PostgreSQL; проверить новую и заполненную БД.
- Настроить реальный TMDB token и сетевой доступ из целевого окружения.
- Согласовать FE/BE origin, reverse proxy, HTTPS и хранение конфигурации/секретов.
- Настроить SMTP, если выбран email recovery/verification, и проверить доставку согласованному тестовому получателю.
- Описать запуск одной командой или последовательностью проверяемых команд; контейнеризация возможна, но конкретная технология не является обязательным требованием.

Критерий: сайт открывается на тестовом URL, реальные данные загружаются, аккаунты и пользовательские данные сохраняются после перезапуска, новый разработчик воспроизводит запуск по документации.

### 3. Завершить клиентскую авторизацию и навигацию

- Восстановление сессии через `/v1/me`, сериализованный refresh, очистка auth при отказе и logout.
- Очистка данных предыдущего аккаунта при смене пользователя; серверное избранное загружается для текущего user.
- URL страниц каталога, movie/TV detail, профиля и избранного, обработка неизвестного URL, browser Back/Forward.
- Согласованный процесс восстановления пароля и необходимые FE-страницы.

Критерий: перезагрузка на карточке сохраняет адресуемую страницу, истёкший access обновляется корректно, отозванная сессия выводит на вход; данные аккаунтов не смешиваются.

### 4. Сделать рабочими все разделы текущего интерфейса

- Рецензии и ответы: список, создание, редактирование, удаление, пагинация, права владельца.
- Оценки: ввод, редактирование, согласованная шкала; различать TMDB и пользовательские оценки.
- Профиль: реальные рецензии и статистика. Счётчики получать из данных/агрегатов, а не подставлять 0.
- Избранное: миграция, уникальность user + media, BE add/remove/list, FE загрузка независимо от текущего каталога.

Критерий: пользователь создаёт рецензию и оценку, видит их в карточке и профиле; избранное сохраняется после перезагрузки и на другом устройстве; другой пользователь не может изменять чужие записи.

### 5. Довести каталог и интерфейс

- Определить стабильные подборки и последовательную пагинацию; убрать обещание «всех фильмов из базы» для случайной ограниченной выдачи.
- Сделать поиск и фильтры согласованными с доступными полями и полным объёмом результатов, обеспечить очистку/сброс поиска.
- Разделить loading, empty, error и частичные данные; добавить повтор запроса и обработку отсутствующего постера/detail.
- Проверить адаптивность, клавиатурную навигацию и состояние форм. Текущие фиксированные многоколоночные layouts требуют браузерной проверки на небольших экранах; вывод о конкретной поломке мобильной версии пока не делается.
- Удалить из пользовательских экранов пояснения о процессе разработки и демонстрационных данных.

Критерий: пользователь понимает, что загружено и что произошло при ошибке; поиск/фильтры не создают ложного впечатления полноты; основные действия доступны на целевых устройствах.

### 6. Подготовить поддержку и принять выпуск

- Проверяемый pipeline сборки/тестов и понятный откат версии.
- Резервное копирование PostgreSQL с проверкой восстановления, политика миграций.
- Проверка здоровья приложения, сбор ошибок и уведомление о важных сбоях; actuator есть, но сами мониторинг/доступы должны быть настроены.
- Ограничения входящего трафика и поддержка общего limiter при нескольких BE instances; очистка старых токенов/сессий, политика повторных TMDB sync.
- Browser E2E: register → login → каталог/поиск → карточка → review/rating/answer → favorites → profile → refresh → logout; отдельно recovery и перезапуск приложения.

Критерий: проверены и пользовательские действия, и сохранность данных, и способ обнаружить/восстановить отказ. Наличие работающего dev-сервера само по себе этот этап не закрывает.

## Структура кода: что менять, а что сохранить

BE уже разделён на controllers, DTO, services, repositories, entities, security и integrations. Аудит не даёт оснований для полной смены этой архитектуры. Изменения должны дополнять существующие слои и миграции.

Активный FE сосредоточен в `App.tsx` и отключает TypeScript-проверку. По мере подключения функций стоит выделить `auth`, `catalog`, `reviews`, `favorites`, `profile`, общий API-клиент, типы, маршруты и состояния запросов; включить проверку типов и убрать неиспользуемый шаблонный код. Само разнесение файла по папкам не означает завершение функции: готовность определяется критериями выше.

Для запуска критичны сначала аккаунты/данные, рабочие интеграции и основные разделы. Косметические улучшения и масштабирование сверх выбранной нагрузки могут идти после приёмки основного сайта. Оценку сроков можно делать после фиксации продуктовых решений по рейтингу, восстановлению доступа, редактированию профиля и целевому окружению.
