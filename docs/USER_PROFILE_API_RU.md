# API профиля пользователя

Реализовано 21 сентября 2026. Изменения относятся только к backend; frontend не изменялся.

## Что хранится

- никнейм;
- URL аватара;
- био;
- предпочтительные жанры, страны и типы контента (`MOVIE`, `TV`);
- оценки пользователя;
- рецензии пользователя;
- лайки, поставленные рецензиям;
- авторские лайки ответам на рецензию.

Статистика профиля содержит:

- `reviews` — количество рецензий;
- `ratings` — количество оценённых фильмов и сериалов;
- `receivedLikes` — лайки на рецензиях пользователя;
- `givenLikes` — лайки, поставленные пользователем;
- `authorLikesReceived` — ответы пользователя, отмеченные автором исходной рецензии.

## Основные endpoints

| Метод | URL | Доступ | Назначение |
|---|---|---|---|
| `GET` | `/v1/me/profile?activityLimit=20` | Bearer | Собственный профиль, включая email, статистику и последние оценки/рецензии |
| `PUT` | `/v1/me/profile` | Bearer | Полная замена редактируемых данных профиля |
| `GET` | `/v1/users/{userId}/profile?activityLimit=20` | публичный | Публичный профиль без email |
| `GET` | `/v1/users/{userId}/ratings?page=0&size=20` | публичный | История оценок с пагинацией |
| `GET` | `/v1/reviews?userId={userId}` | публичный | История рецензий с пагинацией |
| `PUT` | `/v1/me/ratings/{mediaType}/{tmdbId}` | Bearer | Создать или изменить оценку |
| `DELETE` | `/v1/me/ratings/{mediaType}/{tmdbId}` | Bearer | Удалить собственную оценку |
| `PUT` | `/v1/reviews/{reviewId}/like` | Bearer | Поставить лайк чужой рецензии; повторный запрос безопасен |
| `DELETE` | `/v1/reviews/{reviewId}/like` | Bearer | Снять собственный лайк |
| `PUT` | `/v1/answers/{answerId}/author-like` | Bearer, автор рецензии | Отметить ответ авторским лайком |
| `DELETE` | `/v1/answers/{answerId}/author-like` | Bearer, автор рецензии | Снять авторский лайк |

Создание или изменение рецензии автоматически создаёт или обновляет оценку того же произведения. Удаление рецензии не удаляет оценку: оценка остаётся отдельной частью истории пользователя.

## Изменение профиля

```http
PUT /v1/me/profile
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "username": "movie_fan",
  "avatarUrl": "https://cdn.example.com/avatars/movie-fan.png",
  "bio": "Люблю фантастику и детективы",
  "preferences": {
    "genres": ["Фантастика", "Детектив"],
    "countries": ["Корея", "США"],
    "mediaTypes": ["MOVIE", "TV"]
  }
}
```

Чтобы очистить аватар или био, передать `null`. Никнейм и объект `preferences` обязательны, так как `PUT` заменяет полное редактируемое состояние.

Ограничения:

- никнейм: 1–80 символов, без управляющих символов, уникален без учёта регистра;
- аватар: HTTP(S) URL не длиннее 1024 символов;
- био: не длиннее 1000 символов;
- до 50 жанров и стран, каждое значение не длиннее 80 символов;
- повторяющиеся предпочтения нормализуются и не сохраняются дважды.

## Добавление оценки

```http
PUT /v1/me/ratings/MOVIE/550
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "rating": 9,
  "title": "Бойцовский клуб",
  "posterPath": "/poster.jpg"
}
```

Оценка должна быть целым числом от 1 до 10. Для одной пары `пользователь + тип + TMDB ID` хранится одна актуальная оценка.

## Пример ответа профиля

```json
{
  "userId": "00000000-0000-0000-0000-000000000001",
  "username": "movie_fan",
  "avatarUrl": "https://cdn.example.com/avatars/movie-fan.png",
  "bio": "Люблю фантастику и детективы",
  "statistics": {
    "reviews": 3,
    "ratings": 8,
    "receivedLikes": 12,
    "givenLikes": 7,
    "authorLikesReceived": 2
  },
  "preferences": {
    "genres": ["Фантастика", "Детектив"],
    "countries": ["Корея", "США"],
    "mediaTypes": ["MOVIE", "TV"]
  },
  "ratings": [],
  "reviews": []
}
```

`ratings` и `reviews` в агрегированном ответе ограничиваются параметром `activityLimit` от 1 до 50. Полную историю FE получает через отдельные endpoints с пагинацией.

## Хранение и изоляция

Миграция `V12__user_profiles_and_interactions.sql` добавляет профильные поля и таблицы `user_ratings`, `review_likes`. Все записи связаны внешними ключами с `users`; уникальные ограничения не позволяют создать несколько оценок или лайков одного типа для одной пары сущностей.

Старые оценки из рецензий переносятся в `user_ratings` при применении V12, включая рецензии без заполненного `media_id`.
