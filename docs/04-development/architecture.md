# Архитектура

> **Цель:** единое описание компонентов и интерфейсов системы · **Обновлено:** 23.10.2026 · **Ответственный:** Иван Зуев (BE), Анна Киракосян (FE)

## Схема

```
Браузер (десктоп / планшет)
   │  HTTPS, JSON
   ▼
nginx ── /        → статические файлы фронта (dist/)
      └─ /api/    → бэкенд Spring Boot (порт 3000)
                       ├─ PostgreSQL (prod) / H2 (dev)
                       └─ TMDB API (данные фильмов)
Яндекс.Метрика, GA4 ← скрипты в браузере
```

## Компоненты

| Компонент | Технологии | Роль |
|---|---|---|
| Фронтенд | Vite, чистый JS, один модуль данных `src/api.js` | Интерфейс зрителя, медиа и автора (Эхо Studio). Без бэкенда работает на демо-данных |
| Бэкенд | Spring Boot 3.4.3, Java 21 | REST API, бизнес-правила, модерация, расчёт оценок и баллов |
| БД | PostgreSQL (prod), H2 (dev) | Пользователи, сессии, рецензии, оценки, лайки, предпочтения |
| TMDB | REST (провайдер `stub` / `http`) | Карточки фильмов, состав, постеры |
| Аналитика | Яндекс.Метрика, GA4 | События и воронки, см. [план аналитики](../05-business/analytics-plan.md) |

## Принципы

- Фронтенд не знает о БД и общается с сервером только через API. Все запросы собраны в `src/api.js`.
- Работа с внешними сервисами (TMDB, позже — почта) — только на бэкенде; ключи не попадают в браузер.
- Протокол — REST поверх HTTPS, формат JSON.
- Ошибки — в едином формате: `{ "error": { "code", "message", "details" } }`. `message` пишется по-русски: фронт показывает его пользователю. Коды: `UNAUTHORIZED`, `FORBIDDEN`, `USERNAME_TAKEN` и т. д.
- Сайт и API на одном домене (`/api` через nginx) — CORS не нужен. Для локальной разработки CORS бэкенда разрешает `http://localhost:3000`; при запуске фронта на 5173 используйте `VITE_DEV_PROXY`.
- Ограничения частоты: вход и регистрация; лимит на число рецензий в день (значение уточняется, в старой версии — 10 в день).

## Что отложено после релиза

WebSocket для мгновенных уведомлений, очереди фоновых задач, почтовый сервис, CSRF-токены (сейчас Bearer-токены в заголовке, cookie для авторизации не используются). Старые целевые показатели (10 000 активных пользователей, 3 000 запросов в секунду) — ориентир масштабирования, см. [нефункциональные требования](../03-product/nonfunctional.md).
