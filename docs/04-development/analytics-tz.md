# ТЗ: сбор продуктовой аналитики на Frontend «Эхо»

> **Цель:** требования к сбору событий продуктовой аналитики на Frontend · **Обновлено:** 28.10.2026 · **Ответственный:** Роман (PM)

## 1. Общие сведения

| Параметр | Значение |
| --- | --- |
| Проект | «Эхо» — веб-платформа оценок и рецензий на кино |
| Задача | Реализация сбора событий пользовательского поведения на стороне Frontend |
| Цель | Обеспечить данные для расчёта метрик из карты метрик, основной воронки и параметров юнит-экономики (показы и клики партнёрского блока) |
| Ключевая метрика | NSM = опубликованные рецензии за неделю / WAU |
| Основная воронка | Первый визит → карточка фильма → регистрация → активация (оценка / рецензия / предпочтение) → возвращение |
| Исполнители | Frontend; Backend — приём и хранение событий; PM — приёмка |
| Связанные документы | Карта метрик «Эхо» (xlsx), юнит-экономика «Эхо» (xlsx) |

## 2. Термины

| Термин | Определение |
| --- | --- |
| Событие | Запись об одном действии пользователя с общими полями и параметрами (props) |
| Показ (impression) | Факт видимости объекта: не менее 50% площади в области просмотра в течение заданного времени |
| Сессия | Последовательность действий без перерыва более 30 минут |
| Просмотр страницы | Один переход на страницу, включая смену маршрута в SPA |
| Анонимный пользователь | Посетитель без авторизации, идентифицируется по anon\_id |
| P0 / P1 | Приоритет: P0 — обязательно к релизу, P1 — после релиза |

## 3. Схема сбора данных

1. Frontend фиксирует действие вызовом `track(event_name, props)` и добавляет событие в очередь.
2. Очередь отправляется пачкой на `POST /api/events`.
3. Backend сохраняет события в таблицу `events` БД проекта (собственный сервер, без сторонних сервисов аналитики).
4. Метрики рассчитываются SQL-запросами по таблице `events` согласно карте метрик.

Разграничение ответственности:

| Сторона | Фиксирует |
| --- | --- |
| Frontend | Действия, доступные только в браузере: визиты, просмотры страниц, показы, клики, раскрытия, прокрутку, начало ввода |
| Backend | Действия с записью в БД (регистрация, вход, оценка, рецензия, лайк, предпочтения) — после успешной записи; клики по партнёрским ссылкам через редирект |

События Backend на Frontend не дублируются.

## 4. Требования

### 4.1 Формат события

| Поле | Тип | Обяз. | Описание |
| --- | --- | --- | --- |
| event\_id | UUID v4 | Да | Уникальный идентификатор события; повтор отбрасывается Backend |
| event\_name | string | Да | Имя события из п. 4.2 |
| ts | ISO 8601, UTC | Да | Время действия |
| user\_id | integer / null | Да | ID авторизованного пользователя; null до входа |
| anon\_id | UUID v4 | Да | Хранится в cookie 12 месяцев, создаётся при первом визите |
| session\_id | UUID v4 | Да | Обновляется после 30 минут без активности |
| page\_view\_id | UUID v4 | Да | Обновляется при каждом просмотре страницы |
| page\_type | enum | Да | home, catalog, search, film, profile, author\_profile, media\_profile |
| is\_test | boolean | Да | true на dev / staging и для тестовых аккаунтов |
| props | object | Да | Параметры события по п. 4.2; пустой объект, если параметров нет |

Пример тела запроса `POST /api/events`:

```json
[
  {
    "event_id": "6f1c2a90-...",
    "event_name": "film_card_clicked",
    "ts": "2026-11-02T14:05:31Z",
    "user_id": null,
    "anon_id": "a81d44e0-...",
    "session_id": "c3e9b7f1-...",
    "page_view_id": "9b02d6c3-...",
    "page_type": "home",
    "is_test": false,
    "props": { "film_id": 123, "list_type": "home_popular", "position": 4 }
  }
]
```

### 4.3 События, фиксируемые Backend

На Frontend не реализуются. Требования к Frontend — в колонке «Участие Frontend».

| Событие | Момент фиксации | Участие Frontend |
| --- | --- | --- |
| user\_registered, user\_logged\_in | После создания аккаунта / успешного входа | Передавать anon\_id и session\_id в запросах регистрации и входа |
| rating\_submitted, film\_preference\_added / removed | После записи в БД | — |
| review\_submitted, review\_published, review\_rejected, review\_removed | После отправки / решения модератора | Передавать form\_instance\_id в запросе отправки рецензии |
| review\_liked, review\_like\_removed | После записи в БД | — |
| author\_comment\_published, role\_assigned | После записи в БД | — |
| partner\_link\_clicked | При переходе по /go/{integration\_id} | Ссылки партнёрского блока ведут на /go/{integration\_id} |

### 4.4 Правила отправки и ограничения

| Правило | Требование |
| --- | --- |
| Показы | Через IntersectionObserver; один показ на пару (page\_view\_id, объект); при видимости меньше порога событие не отправляется |
| Дедупликация | Повторный клик менее чем через 2 с не отправляется; review\_started — один раз на form\_instance\_id; scroll\_depth\_reached — один раз на порог в рамках page\_view\_id |
| Отправка | Пачкой раз в 5–10 с или при накоплении 20 событий; при закрытии страницы — navigator.sendBeacon |
| Ошибки | Ошибка отправки не влияет на работу интерфейса и не показывается пользователю; одна повторная попытка |
| Персональные данные | Запрещено передавать пароли, токены, тексты рецензий и комментариев, текст поискового запроса (допускается search\_query\_length) |
| Именование | Только события из п. 4.2, snake\_case; новые события и параметры — по согласованию с PM |
| Тестовые данные | На dev / staging is\_test = true и вывод событий в консоль; в production вывод отключён |
| Архитектура кода | Вся логика в одном модуле analytics; в компонентах — только вызовы track() и общий хук показов |

## 5. Порядок выполнения работ

| Этап | Работы | Исполнитель | Результат |
| --- | --- | --- | --- |
| 1 | Согласование контракта POST /api/events: массив событий, ответ 204, дедупликация по event\_id, авторизация не обязательна | Frontend + Backend | Утверждённый контракт |
| 2 | Модуль analytics: track(), общие поля, очередь, отправка, sendBeacon | Frontend | Модуль в репозитории |
| 3 | Идентификаторы anon\_id, session\_id, page\_view\_id; передача anon\_id и session\_id в запросах регистрации и входа | Frontend | Идентификаторы в каждом событии |
| 4 | Общий хук показов на IntersectionObserver | Frontend | Хук для карточек, рецензий, партнёрского блока |
| 5 | Разметка событий P0 | Frontend | События 1–9 из п. 4.2 |
| 6 | Проверка по критериям приёмки на staging | Frontend + PM | Заполненная таблица п. 6 |
| 7 | Разметка событий P1 | Frontend | События 10–15 из п. 4.2 |

## 6. Критерии приёмки

| № | Проверка | Ожидаемый результат |
| --- | --- | --- |
| 1 | Одно действие пользователя | Одна запись в таблице events, без дублей |
| 2 | Общие поля | Заполнены во всех событиях согласно п. 4.1 |
| 3 | Анонимный визит → регистрация | До входа user\_id = null; после регистрации анонимные события связаны с аккаунтом по anon\_id |
| 4 | Основная воронка: первый визит → карточка фильма → регистрация → оценка → форма рецензии → отправка | Все события Frontend и Backend присутствуют в правильном порядке |
| 5 | Карточка или блок видны менее 1 с | Показ не зафиксирован |
| 6 | CTR по блокам | Для главной, каталога и поиска передаётся корректный list\_type |
| 7 | Закрытие вкладки с неотправленными событиями | События доставлены через sendBeacon |
| 8 | Персональные данные | В событиях нет паролей, токенов и текстов |
| 9 | Отказ эндпоинта /api/events | Интерфейс работает без ошибок для пользователя |
