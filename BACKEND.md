# Эхо — инструкция для бэкенда

Документ для того, кто подключает базу данных и API к фронтенду «Эхо».
Подробный контракт (пути, тела запросов, форматы ответов) — в [API.md](API.md). Здесь — порядок работы и правила.

## 1. Как устроен фронт

- Фронт собирается Vite в набор статических файлов (`npm run build` → `dist/`). Node.js на сервере не нужен.
- Весь обмен с сервером — **только в `src/api.js`**. Остальные файлы (`app.js`, `styles.css`) трогать не нужно.
- Если переменная `VITE_API_URL` пустая, фронт работает на демо-данных из `src/mock-data.js`.
  **Формат объектов в `mock-data.js` = формат ответов API.** Если не ясно, какое поле нужно, смотрите туда.
- Адрес API вшивается в сборку: после смены `.env` выполните `npm run build` заново.

## 2. Быстрый старт

```bash
git clone https://github.com/SaTayouNy/EchoWeb.git
cd EchoWeb
npm install
cp .env.example .env
```

Локально, бэкенд на `http://localhost:8000`:

```env
VITE_API_URL=/api
VITE_DEV_PROXY=http://localhost:8000
```

```bash
npm run dev     # http://localhost:5173, запросы /api/* уходят на localhost:8000 без префикса /api
```

Без префикса значит так: фронт вызывает `/api/movies`, а бэкенд получает `/movies`. CORS локально не нужен.

## 3. Что реализовать (минимум для запуска)

Порядок, в котором удобнее делать:

1. **Чтение данных.** Фронт вызывает их при каждом открытии сайта:
   `GET /movies`, `GET /reviews`, `GET /authors`, `GET /people`, `GET /users`, `GET /auth/me` (без сессии — `401`).
   После этого сайт полностью отображается на данных из БД.
2. **Вход и сессия:** `POST /auth/login`, `/auth/register`, `/auth/author/login`, `/auth/author/register`, `/auth/logout`.
   Сессия по cookie (HttpOnly, SameSite=Lax). Регистрация — только логин и пароль, без почты.
3. **Действия зрителя:** лайк рецензии, оценка без рецензии, публикация рецензии, предпочтения (топ-5), редактирование профиля.
4. **Действия автора (Эхо Studio):** лайк автора на рецензию, публикация авторского комментария к фильму.

Полная таблица запросов — в API.md, разделы 1–4.

## 4. Бизнес-правила, которые должен проверять сервер

Фронт проверяет часть правил у себя, но источником истины должен быть сервер.

- **Оценка:** 5 параметров от 1 до 10 (драматургия, персонажи, визуальный язык, звук, впечатление).
  Итог = `round(avg(первые 4) × 10 × (0.4 + 0.6 × (впечатление − 1) / 9))`.
- **Рецензия:** от 150 до 10 000 символов, одна на фильм от пользователя, без редактирования и удаления; проходит модерацию перед публикацией.
- **Лайки:** зритель может поставить и снять лайк. Автор обычные лайки не ставит. Лайк автора ставит только автор и только на рецензии к своим фильмам.
- **Авторский комментарий:** один на фильм от автора. Новая публикация заменяет старую, лайки обнуляются.
- **Предпочтения:** не больше 5 в каждой категории (фильмы, режиссёры, актёры). Счётчик `preferred` у фильма и автора = число пользователей, у которых он в топ-5.
- **Роли:** `user` (зритель), `media` (медиа/критик), `author` (автор, подтверждённый модератором). Заявка автора возвращает `{ "pending": true }` до подтверждения.
- **Статус зрителя:** считается по баллам (`points`). Пороги: Искра 0, Мята 500, Лазурь 1500, Аметист 3000, Рубин 5000, Полярный 8000.

## 5. Важные детали формата

- **id фильмов** — любые числа. Фронт сам переводит их во внутренние индексы, а в запросах отправляет настоящие id.
- **id рецензий** — числа, у новых больше: сортировка «Новые» идёт по `id`.
- **Авторы** сейчас различаются по `name`, поэтому имена должны быть уникальными. Предпочтения по режиссёрам и актёрам передаются именами.
- **Даты** приходят готовыми строками для показа: `"22 сентября 2026"`.
- **Картинки** (`poster`, `avatar`, `image`) — URL. Если картинки нет или она не загрузилась, фронт показывает заглушку.
- **`likedByMe`** у рецензии и у `authorComment` — поставил ли лайк текущий пользователь. Отдавайте его, когда есть сессия.
- **Ошибки:** статус 4xx/5xx и `{ "message": "..." }`. Текст показывается пользователю как есть, поэтому пишите его по-русски.

## 6. Выкладка

```bash
# на сервере или в CI
echo "VITE_API_URL=/api" > .env
npm ci && npm run build      # результат в dist/
```

nginx: сайт и API на одном домене, тогда CORS не нужен.

```nginx
server {
  server_name app.example.ru;
  root /var/www/echo/dist;
  location / { try_files $uri /index.html; }
  location /api/ { proxy_pass http://127.0.0.1:8000/; }
}
```

Если API на отдельном домене (`VITE_API_URL=https://api.example.ru`), на бэкенде нужен CORS:
`Access-Control-Allow-Origin: https://app.example.ru`, `Access-Control-Allow-Credentials: true`,
методы `GET, POST, PUT, PATCH, DELETE`, заголовок `Content-Type`.

## 7. Как проверить

1. Запустите бэкенд и фронт (`npm run dev` с прокси из раздела 2).
2. Откройте `http://localhost:5173/?debug`. Если данные не загрузились, на странице появится «Не удалось загрузить данные» с текстом ошибки.
3. Пройдите сценарии: войти, открыть фильм, поставить лайк, добавить фильм в предпочтения, опубликовать рецензию; войти как автор, поставить лайк автора в «Мнениях зрителей», опубликовать комментарий.
4. Во вкладке Network браузера сверьте запросы с API.md.

Вопросы по формату — к PM (Роман Стяжкин). Если в API.md чего-то не хватает, это дорабатывается в `src/api.js` и API.md, интерфейс не трогается.
